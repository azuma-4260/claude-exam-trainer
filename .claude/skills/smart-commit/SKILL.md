# smart-commit スキル

変更されたファイルを分析し、関連する変更を論理的にグループ化して、適切なコミットメッセージで複数のコミットを自動作成します。

**重要: このスキルの呼び出し自体がコミット実行の承認です。** コミット計画を提示したあとは、ユーザーへの確認を挟まずそのままコミットまで実行してください。ただし以下の場合のみ一時停止して確認します:
- 未追跡ファイルにバイナリ・一時ファイル（`.xlsx`/`.xls`/`~$`/`.DS_Store` 等）が含まれ、コミット対象に含めるか判断が必要な場合
- 機密情報・認証情報を含む可能性のあるファイルが検出された場合

## 処理手順

### 1. 変更ファイルの確認と分析

まず、以下のコマンドを並列実行して現状を把握してください：
- `git status` で変更されたファイルリストを取得
- `git diff --stat` で変更の統計情報を取得
- 各変更ファイルの `git diff` で具体的な変更内容を確認

### 2. 変更の自動分類

以下のカテゴリーに基づいて変更を分類してください：

#### **設定系** (`settings`)
- ファイル: `worldbuilding/confirmed_settings.md`, `worldbuilding/*_settings.md`
- コミットタイプ: `feat:` (新設定追加) / `fix:` (設定誤り修正) / `update:` (設定更新)

#### **キャラクター系** (`character`)
- ファイル: `worldbuilding/characters/*.md`（1キャラ1ノート）
- コミットタイプ: `feat:` (新キャラ追加) / `update:` (既存キャラ更新)

#### **年表/歴史系** (`timeline`)
- ファイル: `worldbuilding/timelines/*`, `worldbuilding/*_history.md`, `worldbuilding/two_nations_history.md`, `worldbuilding/foreshadowing_ledger.md`, `worldbuilding/story_bible/*`
- コミットタイプ: `feat:` (新規作成) / `update:` (更新)

#### **ストーリー/執筆系** (`story`)
- ファイル: `drafts/**/*.md`（設計書 `drafts/designs/` を含む）, `drafts/公開/**`（publish-prep成果物・`.txt`含む）
- コミットタイプ: `feat:` (新規執筆) / `update:` (章の更新) / `fix:` (誤字脱字修正)

#### **世界観/地図系** (`worldbuilding`)
- ファイル: `worldbuilding/*.md` (上記以外), `worldbuilding/organizations/*.md`, `worldbuilding/nations/*.md`, `worldbuilding/locations/*.md`, `worldbuilding/MOC/*.md`, `worldbuilding/_meta/*.md`, `*.html` (地図)
- コミットタイプ: `feat:` (新規設定) / `update:` (設定拡張)

#### **技術/設定ファイル系** (`config`)
- ファイル: `.claude/*`（skills含む）, `CLAUDE.md`, `GEMINI.md`
- コミットタイプ: `docs:` (ドキュメント更新) / `chore:` (設定変更) / `feat:` (skill新規追加)

#### **その他** (`misc`)
- 上記に該当しないファイル

### 3. グループ化のルール

1. **同じカテゴリー内で関連性が高い変更**: 1つのコミットにまとめる
   - 例: `confirmed_settings.md` と `characters/カガミ・シン.md` の両方で「カガミの超能力名修正」→ 1コミット
2. **異なるカテゴリーでも同じ目的の変更**: 1つのコミットにまとめる
   - 例: `CLAUDE.md` と `confirmed_settings.md` で「教皇の設定追加」→ 1コミット
3. **独立した大きな変更**: 個別のコミットに分離
   - 例: 「第1章執筆」と「第2章執筆」→ 2コミット
4. **技術的変更と内容的変更**: 分離する
   - 例: `.claude/settings.local.json` の変更と `drafts/chapter_01.md` の執筆 → 2コミット

### 4. コミットメッセージの生成

```
<type>: <日本語の簡潔な要約>

<必要に応じて詳細説明>
```

#### Type の選択基準
- `feat:` - 新機能・新設定・新コンテンツの追加
- `fix:` - バグ修正・設定誤り訂正・誤字脱字修正
- `update:` - 既存設定の更新・拡張・改善
- `docs:` - ドキュメントのみの変更
- `refactor:` - 構造の整理・リファクタリング
- `chore:` - ビルド・設定ファイルの変更

#### メッセージの例
- `feat: カガミ・シンの詳細設定とJokers部隊構成追加`
- `fix: カガミの超能力名を「斬鉄」から「写鏡」に修正`
- `update: 第N章「章タイトル」プロット詳細化`
- `feat: 第N章「章タイトル」初稿執筆`

### 5. 未追跡ファイルの処理

`??` (untracked files) については、以下のように処理してください：

1. **コミットすべきファイル**（確認不要・そのままコミット対象に含める）:
   - `.md` ファイル（worldbuilding, drafts 配下）
   - `.html` ファイル（地図など）
   - `.claude/skills/**`（スキル定義・リファレンス・スクリプト）
2. **除外を推奨するファイル**（コミット対象から除外し、含めるか確認する）:
   - `.xlsx`, `.xls` (Excelファイル)
   - `~$` で始まる一時ファイル
   - `.DS_Store` などのシステムファイル

### 6. コミット計画の提示

以下の形式で、コミット計画を提示してください。**提示後はそのまま手順7のコミット実行に進みます**（承認待ちはしません）：

```markdown
## 📋 コミット計画

以下の変更を **N個のコミット** に分けて実行します：

### コミット 1: <type>: <要約>
**含まれるファイル:**
- `path/to/file1.md` (+XX -YY行)

**変更内容:**
<簡単な説明>

---

### 未追跡ファイル (確認が必要なものがある場合のみ)
- `手書き年表.xlsx` → 除外（非推奨: バイナリファイル）。含める場合は指示してください。
```

### 7. コミット実行

計画を提示したら、続けて以下の手順で実行してください：

1. 各コミットグループごとに `git add <ファイル...>` → `git commit -m "<メッセージ>"`
2. 各コミット後に `git log -1 --oneline` で結果を確認
3. すべてのコミットが完了したら、最終確認として `git status` を実行

## 注意事項

- 関連性のない変更を1つのコミットにまとめないでください
- コミットメッセージは変更の「何を」ではなく「なぜ/何のために」を重視してください
- 1コミット = 1つの論理的変更。大きな変更は分割してください
- Conventional Commit形式を厳守し、メッセージは日本語で簡潔に
- スキルの呼び出し自体が承認であるため、計画提示後は確認を挟まずコミットを実行してください（手順5・冒頭の例外を除く）
