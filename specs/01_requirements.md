# 01. 要件定義(v1.3)

**v1.3(2026-09-29, S-3)**: F 合格(9/27)を受け、目的を P 版に更新。FR-10 を「学習スコープ(F / P / F+P)」として全面改訂し、FR-5〜FR-8 にスコープと exam 固有値の扱いを追記。

## 目的

CCAR-F(2026-09-27)と CCAR-P(2026-12-12)に一発合格する。**未提出の固定フォーム模試(初回受験)の素の正答率 85% を 2 回連続**で出せる状態を試験前の凍結日までに作る(rehearsal スコアは判定に含めない。readiness は exam ごとに独立に判定)。

- CCAR-F: 9/27 に合格済み(以上の目標は F では 9/20 を期限として運用した)
- CCAR-P: P の固定フォーム初回受験 2 回連続 85% を **12/5(P 凍結)**までに出す。P のフォーム本数・問題数は T-pmock で確定(`09`)

## ユーザー像

- 単一ユーザー。マルチテナント・共有機能なし
- Claude Code を日常使用する開発経験者。本アプリのコードは書かない
- 1 日 60 分。スキマ時間はスマホ、腰を据えるときは PC

## 機能要件

### FR-1 シラバスマップ

- ドメイン → タスクステートメント → トピックの 3 階層ツリー。トピック別の問題数・習熟度を可視化、問題 0 トピックに ⚠

### FR-2 (v1.2 で廃止)初期診断テスト

- 実装しない。最初の実学習 attempt から習熟度を推定する(`04` の retention 既定値 0.3 により、初期の出題優先度は概ねドメイン重みで決まる。これで「弱点を決め打ちしない」という要求は満たされる)

### FR-3 一問一答モード(Quick Drill)

- 1 セッション 5〜20 問、片手・タップ完結
- フラッシュ(自己評価 4 ボタン)+ 短問 MCQ(正誤から自動レーティング)

### FR-4 本番形式演習(Practice)

- シナリオ付き MCQ を 1 問ずつ即時採点。日本語解説(全選択肢の正誤理由)+ refs
- 出題プール: Practice 専用シナリオ MCQ(フォーム非収載)、独立 MCQ、**提出済みフォームから解放された問題**。未提出フォーム収載問題は出さない(holdout ゲート)

### FR-5 模試モード(Mock Exam)

- **exam ごとの固定フォーム**。実行時ランダム合成なし
  - CCAR-F 固有値: 3 本(form A/B/C、各 60 問・4 シナリオ・重複なし)
  - CCAR-P: 本数・問題数・ドメイン配分・シナリオ有無は T-pmock で `03` §mock_forms に仕様化する(CP0 の Guide 記録が根拠)
- フォームは `(exam, form_id)` で識別する。提出状態・holdout・readiness・rehearsal 判定は exam ごとに独立(F の提出は P のフォームに影響しない)
- **holdout ゲート(eligible_modes より先に評価。学習スコープ判定の次)**: 未提出フォーム収載問題は、その正確なフォーム以外(Practice / Drill / ミニ模試 / 間違いノートを含む)に一切出題しない
- フォーム初回提出後、収載問題は Practice に解放(srs_eligible=false は維持、FSRS カード化しない)。誤答・未回答は間違いノート対象
- **開始時の availability 検証**: フォーム内に status≠active または現行 rev の未解決フラグが 1 問でもあれば、そのフォームは開始不可(実行時の代替差し込み禁止)。次の有効な未実施フォームを選択。全フォーム block 時は Mock 開始を拒否し悪問修正を要求。進行中セッションは開始時の問題集合を固定し、途中のフラグ追加で問題を除去しない
- 提出済みフォームの再受験は可能だが、スコアは **rehearsal score** として扱い、readiness 判定(85% × 2 回)には使用しない
- ドメイン別ミニ模試: 独立 MCQ プールのみから構成(フォーム収載問題は常に除外)。10〜15 問 / 20〜30 分
- ハーフ模試は任意機能(Phase 4 以降・余力時)
- **中断の定義**: フルは pause 不可・abandon 不可(手動提出 or timeout 提出のみ)。ミニは abandon 可。ページ離脱・スリープ後も同一セッション復元、時計は止まらない。`deadline_at` はサーバー確定、残り時間は `deadline_at - now` の再計算のみ。超過検知時は timeout 提出
- 回答・見直しフラグ・現在位置は操作ごとに即時保存
- **開始候補**(フル・ミニとも)は学習スコープ内の exam のフォーム / ドメインに限る。**進行中セッション**の復元・回答保存・フラグ・提出・timeout 提出はスコープに依存せず、開始時に固定した exam と問題集合で続行する(スコープ切替で進行中の模試が失われたり再開不能になったりしない)
- 採点・解説は提出まで非表示。Mock は FSRS 非更新、attempt は提出時一括生成(`03`)
- レポート: 素の正答率、ドメイン別正答率(重み併記)、誤答一覧。スケールドスコアなし。rehearsal の場合はその旨を表示

### FR-6 SRS と日次キュー

- 詳細 `04`。ホームに「今日のノルマ」(45 分予算内)と「バックログ」を分離表示
- キューは学習スコープ内の exam の問題のみで構成(F+P は 45 分予算を共有、`04`)
- 試験日カウントダウン(スコープ内の試験日が未来の exam。過去の exam は「受験済み」表示)、ペース警告(required_new > 日次上限)
- 試験日を過ぎた exam も復習を継続する(`04` §試験日対応)

### FR-7 間違いノート(導出ビュー)

- 専用テーブルなし、attempt から導出(`03`)
- 対象 mode: practice / mock(提出時一括生成分を含む)。3 連続正解で自動卒業、再誤答で復帰。手動追加なし
- holdout ゲートに従う: 未提出フォーム収載問題はノートに現れない(定義上、mock attempt 生成 = フォーム提出済みなので自然に満たされる)
- 総ざらいモード: Quick Drill 形式の高速周回(practice mode として記録)
- 表示対象は学習スコープ内の exam の問題のみ

### FR-8 ダッシュボード

- ドメイン別習熟度、日別回答数、模試正答率推移(initial / rehearsal を区別)
- 素の正答率・重み付き正答率・85% ラインのみ。実装優先度低、簡略表示可
- 学習スコープ内の exam を集計対象とし、F+P では exam ごとに分けて表示する(ドメインは exam 固有なので混ぜない)

### FR-9 品質フィードバック

- 悪問フラグ(ambiguous / wrong / outdated + メモ)。(question_id, question_rev) 単位、現行 rev の未解決フラグのみ出題除外
- 現行 rev と不一致の旧フラグは superseded とみなし、未解決一覧・出題除外の対象外(`03`)

### FR-10 学習スコープ(v1.3 / オーナー決定 2026-09-29)

- 学習スコープは `ccar-f`(F のみ)/ `ccar-p`(P のみ)/ `both`(F+P)の 3 値。いつでも切り替えられる
- スコープは DB の単一行設定(`03` §study_setting)に保持し、PC・スマホで共有する(端末ごとの Cookie にはしない)。行が無い場合は `ccar-f`(S-3 以前の挙動と同じ)
- スコープ内の exam に絞るもの: Drill / Practice の出題、日次キュー、習熟度、間違いノート、Stats、模試(フル・ミニ)の開始候補
- スコープに依存しないもの: 進行中の模試セッション(FR-5)、未解決フラグ一覧(全 exam を exam ラベル付きで表示)、データエクスポート、readiness / rehearsal 判定(exam ごと)
- スコープ切替は設定行以外(srs_state / attempt / exam_session / question_flag)を一切変更しない
- 試験日を過ぎた exam(F)も選択でき、復習を継続できる。新規導入はペース式により 0(`04`)
- 試験日が未設定の exam を含むスコープは選択不可(fail closed)。試験日は exam ごとのコード定数(F 2026-09-27 / P 2026-12-12)
- 旧 v1.2: 9/27 まで CCAR-F 固定、`exam` フィールドのみ保持(F 合格で解除)

## 非機能要件

| 項目 | 要件 |
|---|---|
| デバイス | スマホ(375px〜)/ PC。モバイルファースト。ダークモードは shadcn/Tailwind 標準対応で追加工数ゼロなら実装、専用調整が要るなら試験後 |
| 同期 | 進捗はサーバー DB。**逐次利用前提**: 複数端末からの同時回答送信はサポート外(分散ロックは実装しない) |
| 回答の耐久性 | **厳密 ACK 方式のみ**(`03` の書込プロトコル)。正誤・解説はクライアント即時表示可。保存 ACK 受信前は Next を活性化しない。保存失敗時は現在問題に留まり Retry 表示。durable outbox・自動巻き戻し・次問先行は実装しない |
| 認証 | パスコード + 署名付きセッション Cookie(`06`) |
| コスト | 月額 0 円。Neon scale-to-zero の wake 遅延は許容(Study 画面進入時のキュー取得が実質的な warm-up になる。keep-alive cron 禁止) |
| オフライン | スコープ外。バンクは static bundle、問題文表示は DB を待たない |
| タイムゾーン | Asia/Tokyo 固定。日次リセット 00:00 JST |

## スコープ外

- 公開・アカウント管理・ソーシャル / 講義テキスト / ネイティブアプリ / API 動的生成/ スケールドスコア / 初期診断テスト / durable outbox / マルチ端末同時書込
