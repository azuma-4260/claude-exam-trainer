# validator が検証していない 2 点(scenarios.yaml 本文スキーマ / フォーム収載問題の srs_eligible)

## 内容
1. **scenarios.yaml の本文スキーマが spec 未定義**。`03` §1 は `scenarios.yaml` の存在のみ記述し、項目(title / 本文 / exam など)は未定義。
   D0-3 の `scenarioSchema` は `id` のみ必須・他キー passthrough で最小化した。C3a でシナリオを書くときに項目を確定し、
   `schema.ts` を `.strict()` に締め直す必要がある。
2. **フォーム収載問題の `srs_eligible: false` を validator は検証しない**。`03` §1 は「フォーム収載問題の標準値: srs_eligible=false」と
   書くが、`06` §バンク静的検証 / `03` §mock_forms の validator 条件リストには含まれない。true が混入しても CI は通り、
   提出後 Practice 解放時に SRS へ流れる(README 決定 6 に反する)。

## 再現手順 / 根拠
- `src/lib/bank/schema.ts` の `scenarioSchema` コメント
- `scripts/validate-bank.ts` 固定フォーム検証ブロック(srs_eligible を見ていない)

## 推奨対応
- (1) C3a 着手時に scenarios.yaml の項目を `03` §1 に追記し、schema を strict 化
- (2) オーナー判断で `06` §バンク静的検証の固定フォーム条件に「srs_eligible=false」を追加するなら、validator に 1 条件 + テスト 1 件を追加(spec 先行)
