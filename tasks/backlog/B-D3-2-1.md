# 開始時 availability 検証とセッション作成が原子的でない(TOCTOU)

## 内容

`POST /api/mock/sessions` は open フラグの読み取り(`loadStartPool`)とセッション作成
(`createSession`)が別クエリのため、読み取り後〜INSERT 前に別タブの `POST /api/flags` が
現行 rev のフラグを追加すると、block 済みフォームを 201 で開始できる(Codex レビュー P2)。

## 再現手順 / 根拠

1. タブ A で `/mock` を開き開始 POST を送る(availability 読み取り直後で停止すると仮定)
2. タブ B で当該フォーム収載問題に `POST /api/flags`
3. タブ A の INSERT が通り、フラグ付きフォームのセッションが作成される

確定決定事項 12(README)は「PC/スマホの同期は逐次利用前提。複数端末からの同時回答送信は
サポート外」であり、個人利用では実害は極小。開始後のフラグ追加でセッションが影響を受けない
こと自体は仕様どおり(問題集合は開始時固定)。

## 推奨対応

createSession のトランザクション内で現行 rev の open フラグ有無を再検証して 0 件を確認する
(store 層の変更)。D4-1(ミニ模試開始)実装時に開始経路を触るため、同時に対応するのが効率的。
