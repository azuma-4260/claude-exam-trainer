# holdout の中間集計が form_id 単独キーで、F と P に同名フォームがあると誤判定する

## 内容
`isSubmitted` は `(exam, form_id)` で提出済みを判定するが、`unsubmittedFormIds` は form_id だけの Set を返す。
`queue/build.ts` はその Set で `poolCtx.forms` を絞って holdout 対象問題集合と `remaining_new` を作る。
F と P に同名の `form-a` があり、F 側だけが提出済みの場合、P 側が未提出なので Set に `form-a` が入り、F の form-a 収載問題まで holdout 扱いになる(逆も同様)。
S-3 で 03 に「中間集計も `(exam, form_id)` で識別する」と明記した。現行本番は F のフォームしか無いので、実害はまだ無い。

## 再現手順 / 根拠
- `src/lib/bank/pool.ts` `unsubmittedFormIds`(`result.add(f.id)`)
- `src/lib/queue/build.ts` の `holdoutIds` 構築(`unsubmitted.has(f.id)`)

## 推奨対応
T-exam に「F+P スコープで同名フォームの片方だけ提出済み」のケースを red で入れ、D6-1 でキーを `(exam, form_id)` に変える(09 の T-exam / D6-1 行に反映済み)。
