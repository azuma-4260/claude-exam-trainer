# rehearsal 判定の同時刻タイブレークが UUID 辞書順(時間的因果ではない)

## 内容

`isRehearsal` は「同一 (exam, form_id) の submitted full で finished_at がより早いもの」の存在で
rehearsal を導出するが、finished_at が完全同時刻の場合のタイブレークが id(ランダム UUID)の
辞書順で、受験順と無関係。Codex 敵対的レビュー(2026-08-27)の medium 指摘。

## 再現手順 / 根拠

同一 form の 2 セッションの finished_at がミリ秒まで一致した場合のみ発動。実運用では
「進行中は全 kind で 1 件」制約により同一人の受験は直列で strict な時刻順が付くため、
このタイブレークは決定性確保のための dead branch(実害は未観測)。

## 推奨対応

「先行セッションが自セッションの started_at までに提出済み」という時間的因果を表す条件に
差し替える(進行中 1 件制約の下では常に well-defined)。S-8 Stats(D4-3)が initial/rehearsal
系列を実装するときに判定を共用するので、その時点で併せて対応するのが自然。
