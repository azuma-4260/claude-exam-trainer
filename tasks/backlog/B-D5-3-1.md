# ローカル `.env.local` に開発専用の APP_PASSCODE / SESSION_SECRET が無く、worktree の dev サーバーでログインできない

## 内容

`specs/06` は「Sensitive 変数は Development に置けないため、ローカルは `.env.local` に開発専用の値を書く」としているが、
main worktree の `.env.local`(`vercel env pull` 由来)には `DATABASE_URL` と `VERCEL_OIDC_TOKEN` しか無い。
`task:start` はこのファイルをそのまま配布するので、各 worktree の dev サーバーは `POST /login` が
`server_misconfigured`(500)になり、実機 DoD 検証の前にログインで止まる。

## 再現手順 / 根拠

1. `npm run task:start <ID>` → worktree で `next dev -p <port>` → `/login` でパスコード送信
2. dev ログに `POST /login 500`(2026-09-22 D5-3 で再現)
3. 回避: `APP_PASSCODE=<dev 用> SESSION_SECRET=$(openssl rand -hex 32) next dev ...` と環境変数で渡す

## 推奨対応

- オーナーが main worktree の `.env.local` に開発専用の 2 変数を追記する(値は表示しない)。`vercel env pull` で
  上書きされるので、pull 後に再追記が必要な旨を `06` §環境の実体か `tasks/README.md` の worktree 注意に 1 行足す
- 併せて `next.config.ts` に `agentRules: false` を検討する(`next dev` が `AGENTS.md` 末尾に自動追記し、
  承認差分に `M AGENTS.md` が混ざる)
