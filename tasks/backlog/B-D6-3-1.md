# ランタイムのバンク利用側が F 固定(`loadBank()` / `bankDir()` の既定 exam)のまま

## 内容
D6-3 で全 exam(`content/ccar-f/` + `content/ccar-p/`)を合成する `loadBankAll()` を追加したが、既存の `loadBank()` は
F のみを返すまま残した(Codex レビュー P1/P2: 利用側は exam 絞り込みが無く、mock 開始は `forms.find(f => f.id === formId)` で
同名 form を取り違えるため)。D6-1 / D6-4 で利用側を `loadBankAll()` + スコープ絞り込み + `(exam, form_id)` 解決に移行する。
syllabus / scenarios の読込も `bankDir()` の既定 `exam = "ccar-f"` に依存したまま:

- `src/lib/queue/serve.ts` `loadSyllabus(bankDir())`
- `src/lib/practice/serve.ts` `loadSyllabus(bankDir())` / `loadScenarios(bankDir())`
- `src/lib/mock/server.ts` `loadScenarios(bankDir())` / `loadSyllabus(bankDir())`
- `src/lib/mistakes/load.ts` `loadScenarios(bankDir())`

P の問題が入ると(CP2 以降)topic 名・シナリオ本文を引けない。シナリオ ID は exam 内でのみ一意(`03` §1)なので、
単純な合成ではなく `(exam, scenario_id)` をキーにする必要がある。

## 再現手順 / 根拠
- 上記 grep `bankDir()` の呼び出し箇所
- D6-3 は D4-1 worktree(`src/lib/mock/server.ts` を変更中)との衝突回避のため呼び出し側を変えていない

## 推奨対応
D6-1(queue / pool / proficiency / 間違いノートのスコープ絞り込み)で syllabus を exam 別に読む。
scenarios の `(exam, scenario_id)` 化は Practice / 間違いノートは D6-1、Mock は D6-4 で扱う。
